# CI/CD Pipeline & Native Compilation Build Time Optimization

We decided to optimize the automated Android NDK and Flutter release pipeline by introducing thin Link-Time Optimization (`lto = "thin"`), parallel LLVM codegen units (`codegen-units = 16`), symbol stripping (`strip = true`), binary caching for `cargo-ndk`, and restricting release compilation targets to physical Android phone architectures (`arm64-v8a` and `armeabi-v7a`), intentionally excluding developer emulator binaries (`x86_64`) from release APK distributions. Compiling un-cached native cryptographic crates across three architectures with default monolithic fat LTO on 2-vCPU GitHub Actions runners required over 12 minutes per release. Restricting targets to consumer mobile chipsets and enabling parallel thin LTO reduces native compilation duration by over 65% while maintaining identical runtime execution speeds, memory-hard Argon2id key derivation, and post-quantum ML-KEM-1024 cryptographic guarantees on real devices.
