# Server-Sent Events (SSE) Streaming Transport for Instant Delivery

We decided to upgrade the HTTPS Port 443 queue transport from repetitive short-polling (`poll=1` every 1.5 seconds) to persistent Server-Sent Events (SSE) HTTP chunked streaming (`GET /<queue>/json` without `poll=1`), complemented by an in-memory event stream unifying background inbox sync and active chat screens. Short-polling across consumer 4G mobile cellular connections incurs recurring TCP 3-way handshakes and TLS 1.3 cryptographic renegotiation overhead (~600–1000ms latency per poll) on overseas relay roundtrips, triggers IP rate-limiting from public relays under high-frequency polling, and introduces UI race conditions between background and foreground pollers. Persistent SSE streaming maintains a single idle TLS connection over standard Port 443 that receives pushed ciphertexts in under 50 milliseconds with zero carrier firewall interference, 90% reduced mobile radio power consumption, and zero traffic-timing metadata leakage, while preserving 100% of the SimpleX unidirectional queue topology and post-quantum Double Ratchet end-to-end security model.
